# REPORT по Практической работе №7

**Вариант 7.** Изменяемый аспект — максимальное количество позиции. Значение: **40**.

## 9. Анализ ошибки из фрагмента
**Фрагмент:** `public List<OrderItem> getItems() { return items; }`
**Ошибка:** Нарушение инкапсуляции. Возвращая прямую ссылку на внутреннюю коллекцию `items`, мы позволяем внешнему коду изменять её в обход бизнес-правил (например, добавлять товары в уже подтвержденный заказ или удалять их).
**Исправление:** В исходном коде уже применен правильный подход — возвращать `List.copyOf(items)`, который создает неизменяемую копию списка.

## 10. Результаты граничных проверок
| Проверка | Что необходимо подтвердить |
|---|---|
| корректное типовое значение | Добавление товара p1 в количестве 10, затем еще 20. Ожидается объединение в одну строку с количеством 30. |
| нижняя граница (включение) | Добавление товара с количеством 1. Ожидается: успешное добавление. |
| нижняя граница (исключение) | Добавление товара с количеством 0 или -1. Ожидается: ошибка `IllegalArgumentException`. |
| верхняя граница (включение) | Добавление товара с количеством 40. Ожидается: успешное добавление. |
| верхняя граница (исключение) | Добавление товара с количеством 41. Ожидается: ошибка `IllegalArgumentException`. |
| пустое или отсутствующее значение | Попытка подтвердить пустой заказ (`confirm()`). Ожидается: `IllegalStateException`. |
| значение неверного формата | Не применимо (количество задается типом `int`, компилятор не пропустит строку). |
| повтор или конфликт данных | Попытка изменить заказ после `confirm()`. Ожидается: `IllegalStateException`. |

## 11. Собственные формулировки
**Какая проверка защищает программу от наиболее вероятной ошибки?**
Проверка в методе `setQuantity` класса `OrderItem` (диапазон 1..40), а также проверка флага `status == OrderStatus.CONFIRMED` в методах `addProduct` и `removeProduct`.

**Какой метод или класс содержит ключевое бизнес-правило?**
Класс `Order` (методы `addProduct` и `confirm`). Именно там реализована логика объединения строк и блокировка изменений.

**Как Activity-диаграмма отражает один конкретный участок кода?**
Ромб «Товар уже есть в заказе» соответствует циклу `for` в методе `addProduct`, который ищет совпадение по `id` товара. Если совпадение найдено, вызывается `increase`.

**Какое изменение требования затронет минимальное количество классов?**
Изменение максимального количества позиции (вариант 7). Достаточно изменить константу `MAX_QUANTITY` в классе `OrderItem`.
